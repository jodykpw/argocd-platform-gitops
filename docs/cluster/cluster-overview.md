# Kubernetes cluster: k8s-1.jodywan.com

- Notes on the cluster and the platform on it. **Picking this up later? Read `how-layer0-works.md` first, then this file.** History is in Git.
- A multi-tenant cluster: two tenant teams (**zeedlogic**, **jodywan**) deploy their own apps only into their own namespaces, with `kubectl` (through Capsule Proxy) and Argo CD.
- The platform team (global, in no tenant) runs the cluster and the support apps. Login is Authentik (OIDC) everywhere.
- **No real tenant users are onboarded yet.** The tenant gate (network, RBAC, guardrails, metrics and logs, GitOps) is built and tested; onboarding is now a decision, not a technical blocker.

- **Traefik:** two replicas spread across nodes, PodDisruptionBudget `minAvailable: 1`; the `traefik` Service is a `LoadBalancer` on `10.1.5.170` (80, 443). Providers: Gateway API, Ingress (default IngressClass `traefik`) and Ingress NGINX compatibility. Dashboard IngressRoute on `traefik-k8s.jodywan.com`, entrypoint `web`. The Gateway `traefik-gateway` (GatewayClass `traefik`, listener `web`) accepts routes only from namespaces labelled `gateway-access=platform`, so a tenant cannot take over a hostname. Tracing to Jaeger: `jaeger.md`.
- **Capsule:** 2 controller replicas on different nodes, webhook certificate generated by Capsule itself (no cert-manager), `forceTenantPrefix` on. Only tenant owners can create tenant namespaces, so the Job `create-tenant-namespaces` in the `tenants` app creates them by impersonating an owner. Both tenants use their 3-namespace quota.
- **Capsule Proxy:** `https://10.1.5.171:9001`, MetalLB address, 2 replicas. Without it `kubectl get ns` is Forbidden for a tenant user (checked), and a cluster-wide list right would show every tenant's and every platform namespace; with it a tenant sees only their own namespaces plus the StorageClasses and IngressClasses their Tenant lists. Platform admins keep using the API server (`https://10.1.5.151:6443`); Argo CD does not use the proxy. Design: `capsule-argocd-integration.md`.
- **Argo CD:** Helm release `argocd`, SSO through Authentik and Dex, the local admin is **off** and `argocd-initial-admin-secret` does not exist. Admins are the Authentik groups `cluster-admin` and `ArgoCD Admins` (`role:admin`); `policy.default` is empty, so tenants get no global rights (theirs live in their own AppProjects, `tenant-gitops.md`). It uses the chart's own HTTPRoute on `traefik-gateway`, listener `web`, with `server.insecure` because pfSense HAProxy terminates TLS. Repo credential `gitlab-group-creds`: rotation in `rotate-argocd-gitlab-token.md`.

## 4. Login to the API server (OIDC, `layer0/oidc/`)

Login uses Authentik. `config.yaml` holds the kube-apiserver flags, and they match the running API server.

- Issuer `https://authentik.jodywan.com/application/o/kube-apiserver-oauth-app/`.
- Username claim `email` (no prefix), groups claim `groups`, group prefix `oidc:`.
- The Authentik provider `kube-apiserver-oauth2-provider` is a **Confidential** client. Headlamp reuses it and needs its client secret.
- `kubectl auth whoami` shows `adminjody@jodywan.com` with groups `oidc:cluster-admin`, `oidc:authentik Admins`, `oidc:Grafana Admins` and `oidc:ArgoCD Admins`. Only `oidc:cluster-admin` is bound to anything; the others are existing Authentik groups kept for later.
- Steps for a new machine: `layer0/oidc/MACBOOK-OIDC-LOGIN.md`. Files in `layer0/oidc/`: `test-permissions.sh` and its results `TEST-RESULTS.md`, `tenant-contexts.sh` (kubeconfig contexts), `TENANT-KUBECONFIG.md` (guide for tenant users), `oidc-cluster-admin.yaml`.

The ClusterRoleBinding `oidc-cluster-admin` (group `oidc:cluster-admin` is `cluster-admin`) is the **only** OIDC binding on the cluster. `oidc-customers-owners` and `oidc-managed-services-owners` were removed because they gave `cluster-admin` and cluster-wide `admin`: do not apply them again.

## 5. Access and roles

The platform team is the global cluster admins; they are not part of any tenant. Today that is adminjody (`adminjody@jodywan.com`).

| Who | How they log in | Group | Role |
|---|---|---|---|
| Platform team (OIDC) | Authentik, `oidc:` group prefix | `oidc:cluster-admin` | `cluster-admin`, through the ClusterRoleBinding `oidc-cluster-admin` |
| Cluster admin (certificate) | `kubernetes-admin` kubeconfig | `kubeadm:cluster-admins` | `cluster-admin`. Break-glass; cannot be revoked per person, so keep it private |
| Kubernetes built-in | n/a | `system:masters`, `system:nodes`, `system:bootstrappers:*`, `system:authenticated` and others | built-in (cluster-admin, kubelet and discovery access) |

To add a platform admin: add their Authentik user to the `cluster-admin` group. They get Kubernetes and Argo CD admin rights with no further change. Group changes apply at their next login.

Capsule gives the two tenants these rights (`capsule-argocd-integration.md`, `tenant-access-model.md`). The tenant groups exist in Kubernetes as `oidc:<group>`; create the matching groups in Authentik and add members before anyone can use them.

| Authentik group | Kubernetes group | Test user | Rights in its tenant's namespaces |
|---|---|---|---|
| `zeedlogic-owners`, `jodywan-owners` | `oidc:<team>-owners` | `owner@zeedlogic.com`, `owner@jodywan.dev` | `admin`, plus create and delete namespaces within the quota (through the Tenant) |
| `zeedlogic-developers`, `jodywan-developers` | `oidc:<team>-developers` | `dev@zeedlogic.com`, `dev@jodywan.dev` | `edit` in all three namespaces (dev, stg, prod); no Roles or RoleBindings |
| `zeedlogic-viewers`, `jodywan-viewers` | `oidc:<team>-viewers` | `viewer@zeedlogic.com`, `viewer@jodywan.dev` | `view` everywhere |

**Permission tests.** `layer0/oidc/test-permissions.sh` runs 78 read-only checks by impersonation (owner, developer, viewer of both tenants, platform namespaces hidden, proxy namespace lists); the expected and actual table is in `layer0/oidc/TEST-RESULTS.md`. Rerun it after any change (Capsule upgrade, Argo CD install, Gateway rules): `cd layer0/oidc && ./test-permissions.sh`. Real logins from the MacBook for the admin and the six test users work.

## 8. Lessons learned

**Argo CD and Helm**

- **Helm charts that generate secrets with `lookup` or random values** (the Garage RPC secret, the Garage UI JWT key) change on every render under Argo CD: point them at an existing Secret.
- **API-server defaults cause false OutOfSync** (HTTPRoute `group`/`kind`/`weight`, StatefulSet `volumeClaimTemplates`, two Gateway API CRDs): use `ignoreDifferences`.
- **Helm replaces lists and merges maps** across values files: keep `extraManifests` (a list) in one file; a second values file may only add map keys. Platform dashboards avoid Helm: `dashboards/platform/*.json` are ConfigMaps from a kustomize source.
- **Charts gate some objects on API discovery.** `helm template` needs `--api-versions monitoring.coreos.com/v1/ServiceMonitor` to render ServiceMonitors; Argo CD passes the cluster's API list itself.
- **Large CRDs** (kube-prometheus-stack): `ServerSideApply=true`.
- **Syncing an app before its Secret exists** leaves the pod in `CreateContainerConfigError` (Garage, Headlamp, Grafana, Prometheus with the Thanos sidecar): create the variable first so External Secrets creates the Secret.
- **Helm `extraManifests` go through `tpl`:** escape `{{ $labels.x }}` as ``{{ `{{ $labels.x }}` }}``.
- **Reloader:** annotation strategy only; platform apps that opt in need an Argo CD `ignoreDifferences` rule for `reloader.stakater.com/last-reloaded-from`. Operator-managed StatefulSets (Prometheus) are restarted by hand.
- **Longhorn and Velero cron schedules are UTC**; systemd timers are local time (BST).
- **`kubectl get backup` is Longhorn's:** use `backups.velero.io`, `restores.velero.io` and `schedules.velero.io` for Velero.

**Versions**

- **Jaeger 2.21 removed `/api/services`, `/api/operations` and trace search**, which Grafana's Jaeger data source uses. Stay on chart 4.13.1 (Jaeger 2.20.0) until Grafana supports `/api/v3`; re-run `tests/jaeger.sh` before bumping. Jaeger metrics in 2.20 have no `_total` suffix.
- **Grafana 13.2 ships Prometheus as a separate plugin**; a transient "Could not load plugin" in the browser cleared by itself (stale cache). Hard-reload first.
- **The Thanos flag is `--downsampling.disable`** (not `.disabled`); check flags with `thanos compact --help` of the image.

**Logging and networking**

- **Fluent Bit caches pod metadata by pod name:** a reused pod name arrives without `namespace`, `pod` and `container` labels. The tests use unique names. New log files are found every `Refresh_Interval` (5 s now; 60 s default).
- **A NetworkPolicy on Loki must allow the `fluent-bit` namespace**, or log shipping stops silently. Re-run `tests/fluent-bit.sh` after any change.
- **`externalTrafficPolicy: Local`** is what lets a NetworkPolicy see the caller's real IP on a LoadBalancer address. Source-IP matching is a network control, not a login.
- **`kubectl run --rm -i` can lose a short-lived pod's output:** tests create the pod, wait, read the logs, and delete it.
- **Calico:** only the `crd.projectcalico.org` objects exist (no v3 API server). Write a guard that only **denies** (never `Pass`: it skips the Kubernetes policies of the tier). The node tunnel addresses (VXLAN, inside the pod CIDR) are what the API server uses to reach pods: any policy that excludes the pod CIDR must list them, or webhooks and `kubectl logs` break.

**Tenancy and policy**

- **Capsule's Tenant `nodeSelector` does nothing here:** it sets a namespace annotation that only the `PodNodeSelector` admission plugin reads, and this API server runs only `NodeRestriction`. Use a ValidatingAdmissionPolicy (CEL, no webhook, no restart): `tenant-baseline/pod-placement-policy.yaml`.
- **A taint is not a wall:** `spec.nodeName` skips the scheduler and the taint, and Pod Security `baseline` does not block it.
- **Pod Security labels** on the tenant namespaces come from the Tenant (`namespaceOptions.additionalMetadata.labels`); owners cannot change them.
- **Capsule's `replications` webhook** blocks owners from editing or deleting what a `GlobalTenantResource` replicated, but only once the object has been labelled (a few seconds after creation).
- **Grafana organizations:** create them (API) before provisioning data sources into them, or Grafana does not start. `org_mapping` needs `org_attribute_path: groups`; set `users.auto_assign_org: false`. Role changes apply at the next login. Grafana's Viewer role has no Explore, so tenant viewers are Editor (the data scope is enforced elsewhere).
- Through Capsule Proxy, developers and viewers see their namespaces only because the RoleBindings carry the label `reflection.proxy.projectcapsule.dev/enabled=true`.
- Group names: Kubernetes sees `oidc:<group>`; Argo CD, Grafana and the UIs see the raw group name (`cluster-admin`).

**Authentik and docker-2**

- Authentik runs in Docker on `ssh adminjody@10.1.5.123` (docker-2, container `authentik-server-1`, `ak shell`). It also serves GitLab, Proxmox and another Grafana: explain risks before touching it.
- The docker-2 Grafana's admin credentials come from its container environment and are used through its API on `localhost:3000`; data sources created that way live only in that Grafana's volume.
- Never print client secrets or keys: pipe them into GitLab variables or Kubernetes Secrets.
- Authentik keeps the browser session: when testing several users, log out or use a private window, and delete that user's token cache (`~/.kube/cache/oidc-login-users/<user>`).
- All Authentik providers are **Confidential**. The Argo CD client secret lives in `layer0/argocd/patch-secret.yaml` (git-ignored, mode 600) or the CI variable; if Dex says `invalid_client`, that secret is stale.
- An OOMKill shows as `RESTARTS` with last state `OOMKilled` (the Capsule Proxy limit is 512Mi; Grafana was raised to 768Mi after 5 OOMKills).
