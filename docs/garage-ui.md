# garage-ui: web console for Garage

- Layer 1, managed by Argo CD, installed **after storage-garage**. Step 6f in `fresh-install-order.md`.
- A web UI for Garage's admin API: bucket browser with upload and preview, access keys with per-bucket permissions, cluster overview.
- Project: <https://github.com/Noooste/garage-ui> (MIT, needs Garage v2.1.0 or newer; we run v2.4.1).
- URL: `https://garage-k8s.jodywan.com/`, login with Authentik (only the group `cluster-admin`).
- Test: `tests/garage-ui.sh` (13 checks). The browser login as a `cluster-admin` user is the one thing to confirm by hand.

## 2. Design choices

- **Same namespace as Garage.** It reads the same Secret and reaches Garage by short names. The namespace is owned by `storage-garage`; this app does not create or label it.
- **Admin API through the pod name.** The Garage chart at tag v2.4.1 has no Service for port 3903, so the UI uses `http://garage-0.garage-headless.garage.svc.cluster.local:3903` (the pod's DNS name). That is the single pod; revisit if Garage ever runs more than one.
- **Secrets are not generated by the chart.** The chart creates a random JWT key at render time, which under Argo CD would change on every refresh. The values name an existing Secret instead (`config.auth.jwt_private_key_secret`).
- **CORS off**, `metrics_public: false`: nothing cross-origin, no unauthenticated metrics.
- **Restricted to platform admins.** The admin token gives full control of Garage (create and delete keys and buckets): the UI is a root console for your S3.

## 3. Dependencies

**Garage UI needs (must exist first)**

| Dependency | Why | Check |
|---|---|---|
| `storage-garage` running (Garage v2.4.1, S3 on 3900) | what it manages | `./tests/storage-garage.sh` passes |
| Secret `garage-admin-token` (key `admin-token`) in namespace `garage` | read by both Garage (as `GARAGE_ADMIN_TOKEN`) and the UI | `kubectl -n garage get secret garage-admin-token` |
| Secret `garage-ui-jwt` (key `jwt-key.pem`, Ed25519) | signs UI sessions | `kubectl -n garage get secret garage-ui-jwt` |
| Secret `garage-ui-oidc` (key `client-secret`) | the Authentik client secret | `kubectl -n garage get secret garage-ui-oidc` |
| Authentik provider and application `garage-ui-oauth-app` | OIDC login | the discovery URL answers |
| DNS (Cloudflare) and an HAProxy entry for `garage-k8s.jodywan.com` | the public hostname, TLS | `./tests/garage-ui.sh` check 2b |
| Argo CD with the `platform` AppProject | `https://helm.noste.dev/` in `sourceRepos` | `kubectl apply -f bootstrap/platform-project.yaml` |

The three Secrets are created by External Secrets from the GitLab variables `garage_admin_token` (`{"admin-token":"…"}`, generate with
`openssl rand -hex 32`), `garage_ui_jwt` (the PEM, generate with `openssl genpkey -algorithm ed25519`) and `garage_ui_oidc`
(`{"client-secret":"…"}`). Details: `external-secrets.md`, `prerequisites.md`.

**Needed by:** nothing. It is a convenience; the CLI and `tests/storage-garage.sh` keep working without it.

**Does not depend on:** Longhorn directly (only through Garage), NFS, Capsule or Tenants.

**If something is missing**

| Symptom | Cause |
|---|---|
| the **Garage pod** stays in `CreateContainerConfigError` and S3 is down | `GARAGE_ADMIN_TOKEN` is set but the Secret `garage-admin-token` does not exist. Create the Secret before syncing the Garage change |
| the UI pod stays in `CreateContainerConfigError` | `garage-ui-jwt` is missing; create it and the pod starts |
| login fails and the UI shows errors from the admin API | a wrong admin token |

## 4. Install, in order

1. `storage-garage` is already running and tested.
2. Both Secrets `garage-admin-token` and `garage-ui-jwt` exist (add the GitLab variables; External Secrets creates them).
3. Commit and push, then apply the AppProject: `kubectl apply -f bootstrap/platform-project.yaml`.
4. Sync `platform-gitops` (creates the `garage-ui` ApplicationSet), then **sync `storage-garage`**. It adds the `GARAGE_ADMIN_TOKEN` environment variable from the Secret and the namespace label `gateway-access=platform`, so the single Garage pod restarts (under 30 seconds; data, layout and `tests/storage-garage.sh` were fine afterwards).
5. Run `./tests/storage-garage.sh` again (Garage still works), then sync `garage-ui`.
6. Run `./tests/garage-ui.sh`, then log in at `https://garage-k8s.jodywan.com/` with a `cluster-admin` Authentik user.

## 5. Login (Authentik) and the hostname

**Authentik** (on `authentik.jodywan.com`)

| Object | Value |
|---|---|
| Provider | `garage-ui-oauth2-provider`: confidential, client ID `aObWap...`, redirect URI `https://garage-k8s.jodywan.com/auth/oidc/callback`, same flows, signing key and scope mappings as the Argo CD provider |
| Application | `garage-ui-oauth-app` ("Garage UI", group Infrastructure) |
| Access | **policy binding: only group `cluster-admin`** may open it (other apps in this Authentik have no restriction) |
| Issuer | `https://authentik.jodywan.com/application/o/garage-ui-oauth-app/` (the discovery answers; the claims include `groups`) |
| Client secret | stored only in Authentik and in the GitLab variable `garage_ui_oidc` |

To undo in Authentik: delete the application `garage-ui-oauth-app`, then the provider `garage-ui-oauth2-provider`.

**Cluster side**

- `overlays/k8s-1/garage-ui/values.yaml`: OIDC settings (`provider_name: Authentik`, issuer, client ID, secret from `garage-ui-oidc`, `team_attribute_path: groups`, `role_attribute_path: groups`, `admin_role: cluster-admin`, `cookie_secure: true`, `root_url: https://garage-k8s.jodywan.com`) and an HTTPRoute (`extraObjects`) for `garage-k8s.jodywan.com` through `traefik-gateway`.
- `appsets/storage-garage.yaml`: the namespace `garage` gets the label `gateway-access=platform` (the Gateway listener only accepts routes from labelled namespaces).
- `appsets/garage-ui.yaml`: an ignore rule for the HTTPRoute's API-server defaults.

**DNS and HAProxy**

1. DNS: a Cloudflare record `garage-k8s.jodywan.com` (same target as `headlamp.jodywan.com`, `217.155.25.4`).
2. HAProxy on pfSense: an ACL and backend for the host `garage-k8s.jodywan.com` to Traefik `10.1.5.170:80`, like the Headlamp entry. **Restrict the source** to your LAN or VPN ranges, because the UI holds the Garage admin token.

**What this means for users**

- With OIDC enabled the UI no longer offers the admin-token login (token login is only the fallback when no other method is configured). The break-glass is the Garage CLI (`kubectl -n garage exec garage-0 -- /garage ...`) and, if the OIDC settings are wrong, reverting `auth.oidc.enabled` in `overlays/k8s-1/garage-ui/values.yaml`.
- A port-forward does not log in: the OIDC callback is the public https URL.
- Only members of the Authentik group `cluster-admin` can reach the app, and they become UI admins (`admin_role: cluster-admin`).

## 6. Test: `tests/garage-ui.sh`

1. The Deployment is ready, the Secrets `garage-admin-token` and `garage-ui-jwt` exist, and the Service exists.
2. `GET /health` on the Service (through a temporary port-forward) returns 200; the public URL answers (check 2b).
3. A short-lived curl pod calls Garage's admin API (`/v2/GetClusterHealth`): **200 with the token, 403 without it**. The token is read from the cluster at run time and is not printed. The script reads the pod's logs after it completes, because with `kubectl run --rm` the last output line can be lost.

Manual check: log in at the public URL and open a bucket.

## 7. Per-tenant access later (not set up)

```yaml
access_control:
  teams:
    - name: zeedlogic
      claim_values: ["zeedlogic-owners"]        # raw Authentik group name (no `oidc:` prefix in the claim)
      bindings:
        - bucket_prefixes: ["zeedlogic-"]
          permissions: ["preset:bucket_owner"]
```

That also needs the Authentik policy binding on `garage-ui-oauth-app` to allow those groups. Remember that the UI's access control is a policy in the UI, not a security boundary.

## 8. Risks and open items

- **The UI is a root console for S3.** Its access control is a UI policy, not a security boundary: anyone with a Garage access key bypasses it, and the UI's own backend uses the admin token.
- **Users matching no team get 403 on everything** once `access_control` exists. Keep a working admin mapping or the Garage CLI as a way back in.
- **Young project, third-party chart repo.** Pin the chart version, review bumps, and consider pinning the image digest.
- **Documentation gaps:** the project README lists some features as roadmap (bucket quotas, per-prefix fine control, audit log). Quotas stay a CLI task for now.
- **Verified:** Garage v2.4.1 reads `GARAGE_ADMIN_TOKEN` from the environment (admin API 403 without the token, 200 with it). **Unverified:** the browser login and the exact OIDC group claim format.

## 9. Secret rotation (Reloader)

`podAnnotations` makes Reloader restart the UI when `garage-admin-token`, `garage-ui-jwt` or `garage-ui-oidc` changes. If you rotate the admin token,
change it in `storage-garage` (Garage) too: both restart by themselves. See `reloader.md`.
